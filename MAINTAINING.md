# Maintaining the guidance package

This file exists only in the template repository (`repo_only`) and is never installed into projects. Its presence switches `manage.py` to template mode, and it tells agents (`AGENTS.md`, top notice) that they are editing the package rather than working in a project.

## Rules for editing the package
1. **Templates stay empty.** Registers (`docs/OPEN_WORK.md`, `docs/VERIFICATION_MATRIX.md`, `docs/PRODUCTION_READINESS.md`) contain only placeholder rows. Record package history in the log below, never in a shipped file. `manage.py` rejects dated entries in registers.
2. **One home per rule.** Before adding a sentence, check the routing table in `AGENTS.md` and `PACKAGE_MANIFEST.json`. Link instead of restating.
3. **Keep AGENTS.md small and concrete.** Aim for strong frontier supervisors + `agent-team` specialists; avoid micro-managing what capable models already do. Keep template `AGENTS.md` concise (ceiling 6,800 bytes across all modules; ~4.7–6.1 KB installed). Edit module-tagged rows under `agents_tables` in `PACKAGE_MANIFEST.json`, then run `python3 manage.py --sync`. Rules must make sense without any optional module installed; link module documents from the routing table, not from rules.
4. **Stay agent-neutral.** Use no tool-specific names or features in packaged policy text. Tool specifics belong in `docs/AGENT_TOOLS.md` (repo-only) and adapter files, and every adapter only points to, exposes, or enforces rules from `AGENTS.md`.
5. **Keep the core stack-neutral.** Stack-specific contracts belong in `profiles/`.
6. **Keep tier sizing proportional.** Prototype stays minimal (`core`); Production adds release rigor (`release-review` + `release`); Enterprise adds traceability, separation of duties, and supply-chain gates.
7. **Every rule that makes agents produce output says where it goes and how it stays bounded.** Never re-introduce cumulative report files or per-change bloat.

## Maintainer team
In this repository, the agent tools load the maintainer team. Its roles live in [maintainer/roles/](maintainer/roles/), and `manage.py --sync` generates them into `.claude/agents/`, `.codex/agents/`, `.github/agents/`, and `.agents/agents/`. The package installs no specialist agents into projects (`agent-team` lives separately). The harness's guidance view leaves the maintainer agents and `maintainer/` out.

| Role | Kind | Use for |
|---|---|---|
| [guidance-editor](maintainer/roles/guidance-editor.md) | implementer | `AGENTS.md`, templates, procedures, profiles, and `README.md` |
| [tooling-engineer](maintainer/roles/tooling-engineer.md) | implementer | `manage.py`, `scripts/verify.py`, and `maintainer/test_install.py` |
| [scenario-evaluator](maintainer/roles/scenario-evaluator.md) | implementer | Scenarios, fixtures, `run_scenario.py`, `maintainer/harness/`, and results |
| [guidance-auditor](maintainer/roles/guidance-auditor.md) | inspector | The independent [package audit](maintainer/AUDIT.md) before a release or consequential merge |

Delegation follows the supervisor rules in `AGENTS.md`. The audit adds its own [independence rules](maintainer/AUDIT.md#independence-rules): a fresh context, where possible another vendor's tool, evidence rather than the author's summary, and read-only. Codex loads these agents only after you trust this repository.

**Generated agent files.** Each file only points to `AGENTS.md` and states the role's responsibilities and limits; the role's `kind` sets the tool list:

| Tool | Implementer, tester | Inspector | Reviewer | Model without a pin |
|---|---|---|---|---|
| Claude Code | `Read, Grep, Glob, Edit, Write, Bash` | `Read, Grep, Glob, Bash` | `Read, Grep, Glob` | The delegating session's model |
| Copilot CLI | `read, search, edit, execute` | `read, search, execute` | `read, search` | The CLI-selected model |
| Antigravity | `view_file, grep_search, replace_file_content, run_command` | `view_file, grep_search, run_command` | `view_file, grep_search` | `inherit` |
| Codex | No per-agent tool list | No per-agent tool list | `[features] shell_tool = false` | The parent session's model |

- Model pins are role frontmatter keys: `claude-model`, `codex-model` (with `codex-effort`), `copilot-model` (which also sets `model-policy: required`), and `antigravity-model` (`inherit`, `flash`, or `pro`), with the pin's source as `model-source:`, which the sync leaves out.
- Enforcement is best-effort. Codex cannot stop an agent editing files, and `sandbox_mode` in an agent file does not override the parent session. Copilot CLI ignores unknown tool names, so only documented aliases are used, with `strict-tools-list: true` and `include-custom-instructions: true`. Antigravity may hang a subagent whose `tools` names an unknown tool. Codex discovers `.codex/agents/*.toml` on its own.
- Sources (checked 2026-11-13): Claude Code <https://code.claude.com/docs/en/sub-agents>; Codex <https://learn.chatgpt.com/docs/agent-configuration/subagents>; Copilot CLI <https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/create-custom-agents-for-cli> and <https://docs.github.com/en/copilot/reference/custom-agents-configuration>; Antigravity <https://antigravity.google/docs/subagents>.

## Workflow for a change
1. Edit source files. For selective skills, edit `docs/procedures/<name>.md`, never `.agents/skills/` or `.claude/skills/`.
2. For a new packaged file, add its `path`, `kind`, and `module` to `PACKAGE_MANIFEST.json`; repository-only files belong under `repo_only`. Update `maintainer/test_install.py` if module/tier contents change.
3. Run `python3 manage.py --sync --update-manifest` then `python3 manage.py`. Both must pass.
4. Run affected scenarios in [maintainer/SCENARIOS.md](maintainer/SCENARIOS.md) only when approved (`maintainer/harness/` costs provider quota). Prefer `run.py --dry-run` first. Keep raw runs outside the repo and record results in [maintainer/RESULTS.md](maintainer/RESULTS.md).
5. For a release or consequential change to `AGENTS.md`, `manage.py`, `scripts/verify.py`, procedures, or the scorer, run the [package audit](maintainer/AUDIT.md) with `guidance-auditor` in a fresh context.
6. Add a log entry below.
